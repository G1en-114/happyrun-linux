# HappyRun 使用教程（手把手版）

> 适用于本文件夹（3km 智能配速最新版）。所有操作都是**双击根目录的 .bat 脚本**，
> 不需要敲命令、不需要复制路径。

---

## 一、5 个双击脚本一览（按使用顺序）

| 顺序 | 双击 | 干什么 | 什么时候用 |
|---|---|---|---|
| ① | `登录抓包.bat` | 弹出抓包窗口，等你用**电脑微信**登录乐跑，把登录态写进 config.json | 第一次用、token 过期了、**换账号** |
| ② | `开始跑步.bat` | 一键正式跑：自动拉取本次打卡点 → 智能规划路线/配速 → 等待模拟时长 → 上传 | 每次跑步 |
| ③ | `实时进度.bat` | 实时看进度条/当前配速/剩余时间，跑完自动显示结果 | 跑步进行时（可随时开关，不影响跑步） |
| ④ | `查看结果.bat` | 看上次过程详情 + 当前账号的有效次数台账 | 跑完之后 |
| ⑤ | `DryRun校验.bat` | 只读彩排：拉真打卡点、规划路线、验证 3/3 覆盖，**不上传不等待** | 第一次用不放心时、换了环境后 |

**记住两条主线就够了：**

```
第一次用 / 换号：  ① 登录抓包 → ② 开始跑步 → ③ 实时进度 → ④ 查看结果
日常同一账号：    ② 开始跑步 → ③ 实时进度 → ④ 查看结果
```

---

## 二、第一次使用（从零开始，10 分钟）

> 前提：电脑已装好 Node.js、Python、mitmproxy（环境装一次就够，见 README 第二节），
> 并且电脑版微信已登录你的微信。

### 第 1 步：登录抓包（约 2 分钟）

1. 双击 **`登录抓包.bat`**
2. 弹出 **UAC 窗口（用户账户控制）→ 点「是」**
3. 会新开一个黑色抓包窗口（mitmproxy），**这个窗口别关**，缩小放着
4. 打开**电脑版微信**（必须是电脑微信，手机不行），进入乐跑小程序，完成登录
5. 看到抓包窗口出现 **`[login] 已写回 config.json`** → 登录态已保存 ✅
6. 抓包窗口可以关了（Ctrl+C 或直接点 ×），回到根目录

> 抓包一次的登录态能用一段时间（token 实测 ≥25 分钟起步，几天不等，过期了重复本步即可）。

### 第 2 步（可选但推荐）：DryRun 彩排

双击 **`DryRun校验.bat`**：会连接服务器拉取**本次真实的打卡点**、规划路线、验证 3 个打卡点全覆盖。
看到 `✅` 和「打卡点 3/3」就说明一切正常。**不上传、不等待，几十秒结束。**
如果报「打卡点无法纳入路网路径」，再双击一次重试即可（打卡点是随机刷的，重跑会换一组）。

### 第 3 步：正式跑（约 11~12 分钟）

1. 双击 **`开始跑步.bat`**
2. 窗口会依次显示：登录态检查 → 拉取打卡点（本次随机 3 个）→ 路网规划 →
   智能配速（例如「最终 3.06km / 668s，计划平均配速 3'39"/km」）→ 开始等待模拟跑步时长
3. **这个窗口别关**（关了跑步就中断了），最小化即可
4. 双击 **`实时进度.bat`** 另开一个窗口看直播：进度条、当前配速、剩余时间、预计完成时刻
5. 到点后自动上传，进度窗口自动弹出最终结果
6. 看到日志里 **「上传成功」** 且返回里 `record_failed_reason` 为空 → 本次有效 ✅

### 第 4 步：核对成绩

双击 **`查看结果.bat`**：台账里新增一条 `✅ 有效`，带距离/配速/打卡数。
手机小程序里也能看到这条记录（距离 3.0~3.1km、配速 3'30"~3'50" 带内、3 个打卡点）。

---

## 三、日常跑（同一账号，token 还没过期）

```
双击 开始跑步.bat → （想看就开 实时进度.bat）→ 跑完看 查看结果.bat
```

就这三下，没有任何多余步骤。token 没过期时 `开始跑步.bat` 不会再弹抓包，直接开跑。

---

## 四、换账号（比如替别人跑 / 换微信登录）

1. 先确认上一个账号**已经跑完**（日志出现「上传成功」或「🎉 完成」；
   没跑完就关窗口放弃即可）
2. 双击 **`登录抓包.bat`**，在电脑微信里**切换到新账号**登录乐跑
   （抓包会自动把 config.json 里的凭证换成新账号的，旧账号台账原样保留）
3. 双击 **`开始跑步.bat`** —— 之后和平时一模一样
4. 新账号的台账是独立文件（`run-history-<新学号>.jsonl`），从第 1 次重新计数

> 不用重启电脑、不用关别的窗口。就算旧的跑步进程没退干净，
> 新开始的「开始跑步.bat」也会自动结束它再开新的。

## 五、实时进度窗口怎么读

```
阶段 running | 进度 1.58km / 3.05km (52%) | 当前配速 3'40"/km (计划 3'37") | 距跑完 04:27 | 预计 20:13 完成
```

- **进度**：模拟跑步的实时距离 / 计划总距离（3.0~3.1km 之间，每次略有不同）
- **当前配速**：起步约 30 秒到 1 分钟偏慢（热身），之后在计划配速上下小幅波动——
  和真人跑步一致；**收尾一定收敛到计划平均配速**（就是最终成绩单上的配速）
- **距跑完 / 预计**：按服务端墙钟校验倒计时，误差 ±15 秒（含上传时间）
- 跑完会自动打印最终结果并退出，不需要手动刷新

## 六、结果怎么看（什么算有效）

| 看哪里 | 有效标志 |
|---|---|
| 跑步窗口日志 | 出现 `上传成功`，返回 JSON 里 `"record_failed_reason":""` |
| 实时进度窗口 | 自动弹出最终结果板块 |
| `查看结果.bat` 台账 | 新增一条 `✅ 有效`（带序号，跨账号独立计数） |
| 手机小程序 | 距离 3.0~3.1km、配速 3'30"~3'50"、3 个打卡点、「自动确认有效」 |

其它结果：`♻ 重复`（当天已有记录）、`⚠ 被拒`（可能当日已达标）、
`✖ 中止`（打卡点没抓到/无法纳入路线，**重跑一次即可**，没上传不算数）。

## 七、常见问题速查

| 现象 | 处理 |
|---|---|
| 抓包窗口一闪而过 / 杀软报毒 | 火绒等会把 mitmweb 当威胁：把 Python 的 site-packages 目录加信任区，或弹窗时点放行 |
| 抓包后一直等不到 `[login]` | 必须用**电脑版微信**登录（手机微信流量不走电脑）；乐跑小程序要真的打开登录一次 |
| 跑步报「登录失效」 | token 过期了：双击 `登录抓包.bat` 重新登录，再 `开始跑步.bat` |
| 报「打卡点无法纳入路网路径」 | 本轮随机打卡点太偏：重跑一次 `开始跑步.bat` 换一组（不会留脏数据） |
| 实时进度显示「当前没有进行中的跑步」 | 跑步没启动或已结束：看 `查看结果.bat`；要跑就先 `开始跑步.bat` |
| 中文乱码 | 不要用老的 `Get-Content` 命令看日志（那是不带编码参数的老毛病）；用 `实时进度.bat` / `查看结果.bat`，或 `Get-Content -Encoding UTF8` |
| 想跑 4km 旧模式 | 命令行：`powershell -File happyrun\start.ps1 -Dist 4 -Time 1320`（智能配速同样生效） |

## 八、必须知道的前提与风险

- **手机微信登录不行**，抓包只抓得到电脑微信的流量
- 跑步等待期间（约 11~12 分钟）**别关「开始跑步」的窗口**，关了就中断（不会留半条记录）
- 同一天同一账号通常只计一次有效（重复跑会提示 `♻ 重复`）
- 服务器规则以服务端实时下发为准（距离/配速/打卡点数都从服务器读，脚本自适应）
- 这是向学校系统提交虚拟数据的工具，被复查（监控对比、体能测试交叉验证）的风险自行评估，
  合理安排频率，别用得过于规律

## 九、文件搬家 / 拷给同学

整个文件夹拷到任何位置都能跑（相对路径设计，实测中文+空格路径也正常）。
拷给别人前：删掉 `happyrun\config.json`（里面是你自己的登录态）和 `run-history-*.jsonl`（你的记录），
对方按「二、第一次使用」走一遍即可。**跨学校不行**——路网是按校区手画的（README 有换校说明）。
