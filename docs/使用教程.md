# HappyRun Linux 使用教程（手把手版）

> 适用：本仓库的 Linux 版。所有命令都在**包根目录**执行（能看到 `start.sh` 的那一层）。

---

## 一、6 个脚本一览

| 顺序 | 命令 | 干什么 | 什么时候用 |
|---|---|---|---|
| ① | `./capture.sh --transparent --once` | 起 mitmproxy，等你在客户端里登录乐跑，把登录态写进 `config.json` | 第一次用、token 过期、换账号 |
| ② | `./dryrun.sh` | 只读彩排：拉本次真实打卡点 → 规划 → 校验 3/3，不上传不等待 | 第一次用、换环境 |
| ③ | `./start.sh` | 一键正式跑：探活 → （失效则拉起抓包）→ 智能配速 → 等待 → 上传 | 每次跑步 |
| ④ | `./watch.sh` | 实时进度条 / 当前配速 / 剩余时间 / 预计完成时刻 | 跑步进行时（可随时开关） |
| ⑤ | `./result.sh` | 上次过程 + 当前账号的有效次数台账 | 跑完之后 |
| ⑥ | `./install-ca.sh` | 把 mitmproxy CA 装进系统信任库 | 抓包时客户端报证书错误 |

日常就两条线：

```
第一次 / 换号：  ① 抓包 → ② 彩排 → ③ 跑 → ④ 进度 → ⑤ 结果
同一账号日常：   ③ 跑   → ④ 进度 → ⑤ 结果
```

## 二、第一次使用（约 15 分钟）

### 第 1 步：装环境（只装一次）

```bash
# Arch Linux
sudo pacman -S nodejs mitmproxy

# 验证
node -v          # ≥ 18
mitmproxy --version
```

> 没有 Arch？只要 Node ≥ 18，抓包再装 mitmproxy 即可（`pipx install mitmproxy` 最省事）。

### 第 2 步：登录抓包（约 2 分钟）

```bash
./capture.sh --transparent --once
```

1. 需要 sudo，会提示输入密码（改的是本机防火墙，退出时自动还原）
2. 打开乐跑客户端（电脑微信小程序 / Android 模拟器 / 浏览器），点登录
3. 看到 `[login] 已写回 config.json` 即成功，脚本检测到文件变化后 2 秒自动退出
4. 如果客户端一直转圈 / 报证书错误：先 `./install-ca.sh`，重启客户端再抓

抓到的登录态在 `happyrun/config.json`，**不要提交、不要外传**。

### 第 3 步（推荐）：彩排

```bash
./dryrun.sh
```

看到 `打卡点 3/3` 就说明路线能覆盖本次打卡点。
如果提示「打卡点无法纳入路网路径」，直接重跑一次（打卡点是随机抽的）。

### 第 4 步：正式跑（约 11~12 分钟真实等待）

```bash
./start.sh
```

输出会依次显示：登录态检查 → 拉取打卡点 → 路网规划 → 智能配速（例如「最终 3.06km / 668s」）
→ 开始等待 → 上传。**这个窗口别关**（Ctrl+C 或关掉 = 中止）。

另开一个终端看直播：

```bash
./watch.sh
```

按 `o` 用浏览器打开实时轨迹图（`http://127.0.0.1:8947/`），按 `q` 退出观看界面（不影响跑步）。

### 第 5 步：核对

```bash
./result.sh
```

台账新增一条 `✅ 有效`，带距离 / 配速 / record_id。
手机小程序里也能看到这条记录（3.0~3.1km、配速 3'30"~3'50"、3 个打卡点）。

## 三、日常跑（同一账号）

```
./start.sh      # 跑
./watch.sh      # 想看就开
./result.sh     # 跑完看台账
```

token 没过期时 `./start.sh` 不会再抓包，直接开跑。

---

## 四、换账号

1. 确认上一个账号已经跑完（日志出现「上传成功」/「🎉 完成」）
2. `./capture.sh --once`，在客户端里换号登录乐跑
3. 直接 `./start.sh` —— 新进程读新 uid/token，台账按账号分文件，从第 1 次重新计数
4. `./result.sh --all` 可看所有账号的台账

---

## 五、换学校要改什么

1. 抓包脚本默认抓 `config.json` 的 `baseUrl` 域名；换学校后先改 `baseUrl`，
   并把 `capture/happyrun-capture.py` 里的 `BASE_HOSTS` 加上新域名
2. 用卫星图重画 `happyrun/roadnet.json`（`nodes` 经纬度 / `edges` 节点对 / `venaPoints` 打卡点），
   可以开 `happyrun/tools/editor/路网编辑器.html` 辅助
3. 改 `config.template.json` 里的 `run.centerLat/centerLon` 到新校区

## 六、参数速查

| 想做什么 | 命令 |
|---|---|
| 默认 3km 智能配速 | `./start.sh` |
| 固定用时 12 分钟 | `./start.sh --time=720` |
| 固定 4.2km | `./start.sh --dist=4.2` |
| 只校验不上传 | `./dryrun.sh` |
| 看实时进度一帧 | `./watch.sh --once` |
| 指定账号台账 | `./result.sh --account=2025xxxx` |
| 抓包不留窗口 | `./capture.sh --transparent --once --no-web` |
| 先看防火墙规则 | `./capture.sh --transparent --dump` |

配置文件 `happyrun/config.json` 里的 `run` 子对象可以覆盖默认：

```json
"run": {
  "distanceKm": 3.0,
  "paceMinS": 210,
  "paceMaxS": 230,
  "centerLat": 37.87,
  "centerLon": 112.55
}
```

## 七、故障速查

| 现象 | 原因 / 处理 |
|---|---|
| TLS / `unable to verify` | Node 太旧或没走系统 CA；升级 Node，脚本会自动加 `--use-system-ca` |
| 抓包窗口一直没输出 | 客户端没走代理；透明模式确认 `sudo nft list table ip happyrun_cap` 有规则，或改用 `--proxy` 并手设代理 |
| 客户端白屏 / 证书错误 | `./install-ca.sh` 后重启客户端（Chrome 系还要 NSS，脚本会尝试） |
| 「不在有效跑步时段」 | 默认 6:00–22:30，等服务端规则时段内再跑 |
| 「打卡点无法纳入路网路径」 | 随机打卡点恰好出圈，重跑换一组 |
| 「登录失效」 | 重新 `./capture.sh --once`，再 `./start.sh` |
| 后台进程残留 | `pkill -f auto-run.mjs`；或 `./watch.sh` 看到「进程已退出」就是没在跑 |
| 防火墙规则残留 | `sudo nft delete table ip happyrun_cap; sudo nft delete table ip happyrun_cap6` |

日志：`happyrun/formal-run.log`；实时状态：`happyrun/formal-run.status.json`。
